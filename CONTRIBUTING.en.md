# Contributing

[Português (Brasil)](CONTRIBUTING.md) · [English](CONTRIBUTING.en.md)

Thanks for wanting to help! This project is an installer + documentation for an Arch/Hyprland environment.

## Ground rules

1. **Do not submit personal data or secrets** (tokens, e-mails, paths with your username, `micro` backups,
   `fish_variables`…). See [`.gitignore`](.gitignore) and [configuration.md](docs/configuration.md#files-left-out).
2. **Do not claim tests you did not run.** In the PR, say which system you tested on (real Arch, VM, container)
   and what you did *not* test.
3. **Always two languages.** Every user-facing string exists in Brazilian Portuguese **and** English.

## Conventions

- **Code language:** scripts, comments, variables, internal identifiers, message keys and technical logs in
  **English**. Only text shown to the user is translated.
- **Messages:** add them with `_m key "English" "Português"` in `scripts/lib/messages.sh`; keep the `%s`
  placeholders in the same order in both languages. Use `t key args…` in scripts.
- **Bash:** `set -Eeuo pipefail`, quote variables, no `eval`, no `rm -rf` on unvalidated paths, `local` in
  functions. Compatible with Bash 4.4+.
- **Installer safety:** nothing in `$HOME` changes before the backup; every write is atomic and recorded in the
  rollback journal; never delete user files; never ask for root without need.
- **Documentation:** `docs/*.md` (PT-BR) and `docs/*.en.md` (EN) change together. Commands, paths and technical
  identifiers must be **identical** in both languages.
- **Dependencies:** edit `packages.txt` stating the **reason** (which binding/script/module needs the package).
  Do not promote items that only appear in comments.

## Environment and tests

```bash
bash tests/test-installer.sh                          # as a regular user (not root)
bash tests/test-docs.sh                               # links, anchors and bilingual pairs
shellcheck -x -S warning scripts/*.sh scripts/lib/*.sh
for f in scripts/*.sh scripts/lib/*.sh tests/*.sh; do bash -n "$f"; done
```

Tests use temporary *fixtures* and **never** touch your `~/.config`. If you change installer behaviour, add a
test to `tests/test-installer.sh`.

## Workflow

1. Fork and create a branch (`fix/…`, `feat/…`, `docs/…`).
2. Small commits, imperative messages (`Add …`, `Fix …`).
3. Open the PR with the [template](.github/PULL_REQUEST_TEMPLATE.md) and tick the checklist honestly.
4. For bugs, use the issue template and attach the log (without personal data).

## Screenshots and previews

Put your screenshots in `assets/screenshots/` (no personal data visible). The installer SVG previews are
generated by `tools/ansi2svg.py` — see [assets/README.md](assets/README.md).
